# 页面 HTML 交付规范

## 适用范围

只在 `delivery_mode=standard`、需要高保真页面或需要 TDD 视觉验收时使用。quick 项目可以先交付页面 MD，不因为流程完整而强制生成 HTML。

## 文件配对

- 页面 MD 和 HTML 位于 `output/pages/`，主文件名相同。
- HTML 必须包含：`<meta name="page-id" content="PAGE-...">`。
- `page-id` 必须与页面 MD 的“页面 ID”相同。
- HTML 只呈现已经被 PRD/Design/Source IDs 支持的行为，不在视觉实现阶段新增产品功能。

## 页面状态

高保真 HTML 至少呈现页面文档中明确要求的初始、加载/提交、成功、失败、空/无权限/异常状态；没有对应需求或真实风险时不机械增加状态。

## 样式与响应式

- 颜色、字体、间距、圆角、动效优先引用 `tokens.css` 的 CSS 变量；不在组件中复制一套新 Token。
- 页面在已确认的桌面、平板和手机宽度下不出现横向溢出或关键内容遮挡。
- 交互状态至少有 hover、active、focus-visible；使用动画时提供针对性 `prefers-reduced-motion` 降级。
- HTML 结构、内容、入口和层级必须与页面 MD 一致；不以“更好看”为理由改动业务流程。

## 本地串联

- 页面之间使用相对 `.html` 路径；外部 `http(s)` 链接保留原值。
- 不确定目标页面、动作后落点或返回 fallback 时，保留待确认项，不猜测跳转。
- 只做一次本地目标存在性扫描；死链、指向自身和无法匹配的动作必须进入交付汇报。

## 视觉证据

- baseline 与 actual 使用相同内容区尺寸、数据和交互状态。
- 视觉验收必须由独立复核者实际看图；截图不能替代真实页面操作。
